## _meta

### 状态
Draft

### 目标
- 提供跨规范共享的最小术语、命名与版本策略入口。
- 避免多个 spec 对同一基础概念重复定义或产生术语漂移。

### 适用范围
- 被多份规范共同引用的基础术语。
- 不属于单一领域规范、但需要在仓库范围内统一的命名风格与版本策略。

### 非目标
- 不替代各领域 spec 的正文规则；具体协议语义与行为约束仍以对应规范为准。
- 不收纳只属于某个领域的字段、协议、状态机或行为约束。
- 不定义具体实现、SDK 接口、框架落地方式或文档维护流程。

### 共享术语
#### trace_id
用于跨服务链路关联的全局标识，同一条业务链路内保持不变。

#### request_id
用于单次请求或单跳调用的标识，可在不同服务间变化。

#### operator
代表业务操作者或用户的标识字段。

#### tenant_id
租户隔离维度标识。

#### app_id
应用或业务系统标识。

### 通用命名
- 跨规范新增 JSON 字段默认使用 snake_case，除非对应 spec 明确声明其他格式。
- 标准 header 名由所属领域 spec 定义；链路相关 header 以 `tracing` 规范为准。
- 标准 string ContextKey 默认使用小写字母、数字与连字符；有对应标准 header 的字段应复用 header 名，没有对应 header 的进程内字段应由所属领域 spec 显式定义，默认使用 `ofa-*` 前缀，且不得使用已保留给 header 的子前缀。
- 未被 spec 显式注册的语言实现内部 context key、局部变量名、常量名不做统一约束。

#### 时间字段
- 对外协议推荐使用 RFC3339 格式。
- 存储层可使用时间戳或 RFC3339，但必须在接口层统一转换。

### 版本策略
规范使用语义化版本号：MAJOR.MINOR.PATCH。

- MAJOR：破坏性变更，旧实现无法兼容
- MINOR：新增可选能力或向后兼容扩展
- PATCH：修订文字、示例或非行为变化
- Stable 状态下不得引入破坏性变更
