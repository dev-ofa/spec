## _meta

### 术语
#### trace_id
用于跨服务链路关联的全局标识，同一条业务链路内保持不变。

#### request_id
用于单次请求或单跳调用的标识，可在不同服务间变化。

#### operator
代表业务操作者或用户的标识字段。

#### tenant_id
租户隔离维度标识。

#### app_id
应用或业务系统标识。

#### audit fields
实体上的创建、更新、删除时间与操作者等审计字段。

### 通用约定
#### 命名风格
- JSON 字段使用 snake_case
- HTTP 头使用全大写与下划线分隔
- 标准链路 header 使用 `OFA_PASS_` 或 `OFA_DIRECT_` 前缀
- 语言实现内部的 context key、局部变量名、常量名不做统一约束

#### 字段类型
- code 为整数
- message 为可读字符串
- data 为任意对象或数组

#### 时间字段
- 对外协议推荐使用 RFC3339 格式
- 存储层可使用时间戳或 RFC3339，但必须在接口层统一转换

### 版本策略
规范使用语义化版本号：MAJOR.MINOR.PATCH。

#### 变更原则
- MAJOR：破坏性变更，旧实现无法兼容
- MINOR：新增可选能力或向后兼容扩展
- PATCH：修订文字、示例或非行为变化

#### 流程要求
- 所有变更必须更新对应规范的状态与版本说明
- Stable 状态下不得引入破坏性变更
